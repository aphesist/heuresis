the benchmark

heuresis retrieves what was in force at a date, cites it, and abstains when it cannot. its benchmark asks whether that is cheaper per correct answer and more reliable than standard rag and agentic search, on three public datasets. it has not been run on the test split.

datasets: hoh, multihoprag, musique generator: claude-haiku-5-5 pre-registration: draft, not frozen

the question

quaestio

on corpora too large for one context window, is a cost-ordered, time-aware, verified-and-abstaining retrieval algorithm cheaper per correct answer and more reliable than standard rag and agentic search?

"more reliable" means a higher penalised score: +1 correct, 0 abstained, −1 wrong, which rewards abstaining over answering wrongly. "cheaper per correct answer" means lower total api cost divided by the number of correct outcomes, at a dated price table. the claim is limited to corpora that do not fit in a context window, to the three datasets, to one generator model, and to the comparison as built.

method

the engine orders its work by cost: cheap local stages first, one model call, then local checks. it filters by validity date before it ranks, so a version not in force at the question's date cannot reach the ranking, and it returns an answer in which every sentence is checked against the passages it cites, or a typed abstention that says why it did not answer. in the default search mode the model may ask for up to four more searches, each run with the question's own as-of date.

every system shares one generator (claude-haiku-5-5, thinking disabled), one sqlite corpus per dataset and one local embedder. the baselines search as of today and are not told the question's date: this is deliberate, the comparison between a system that handles validity and systems that do not. a time-aware copy of each baseline (+asof) is run too, as exploratory, to show how much of any gap is the date filter alone.

pre-registration

PREREGISTRATION.md is a draft, dated 2026-11-11. it will be frozen by a git tag (prereg-v1) after the calibration on dev and before any run on the test split; after the tag, every change goes into its deviations log with its reason and date.

its proposed decision rules: supported only if, on at least two of the three datasets, the engine's penalised score beats both hybrid and agentic at a holm-adjusted p below 0.05, and its cost per correct answer is lower than agentic's with a bootstrap 95% interval that excludes zero. refuted if, among other conditions, the engine does not beat hybrid on hoh, the one dataset where it has a structural advantage. mixed otherwise.

prior contact with the test split

two retrieval-only sanity checks read part of the test split before the draft was written: no system answered a test question, no model was called and nothing was graded. it is a contamination risk and is disclosed as one, in section 2a of the pre-registration.

  • the versioned store with its as-of filter is a large, robust gain. pooled over the three datasets: 0.120 and 0.390 (thinking disabled, n = 300).
  • a plain hybrid baseline that is given the date matches the engine on the temporal set, so the date filter, not the rest of the engine, carries that result.
  • the single-draft engine abstained on 61 to 76 percent of the multi-hop questions and, with the model's default thinking on, lost to the agentic baseline on both (engine minus agentic: musique −0.240 [−0.370, −0.110], multihoprag −0.270 [−0.440, −0.110]).
  • the entailment verifier cannot separate right answers from wrong ones, because the wrong answers' claims are usually true of their passage. this is why verification became a grader of confidence, not a gate, in the redesign.

the redesign these results led to (the search answer mode and the grade decision mode) is not measured. the check is a paid run on dev2, a fresh tuning split, then the test split. sources: results/dev-fixes/NOTES.md, results/dev-fixes/thinking-default/comparison.md, results/dev-calibration/phase1/NOTES.md.
